## Ant Renamer Qt 3.4.0-beta.1

Ant Renamer Qt is a C++/Qt 6 port of [Ant Renamer](https://www.antp.be/software/renamer/) by Antoine Potten: batch file renaming (replace, insert, move, delete, enumerate, change case, regular expressions, EXIF/IPTC/XMP/ID3 tags...) on Windows and Linux.

This is the first beta of 3.4.0, "choosing the files": which files go into the list, and how to find them there. What changes:

- **Filter by name.** "Filter files" (F4) has a new criterion, "Name matches": a list of masks (`*.jpg;IMG_??.png`: `*` and `?`, the whole name must fit, several masks separated by `;`) or a regular expression (found anywhere in the name; `^` and `$` tie it to the start and the end). Capitals do not matter unless "Case sensitive" is ticked. It works together with the date, the time of the day and the size, and a regular expression that does not compile is refused with the reason.
- **Only files named.** "Add folders" and the drag and drop window have a new line with the same masks or regular expression: only the files whose name fits are added. Folders are not concerned. The line is not remembered for the next addition, so that a forgotten mask never leaves files out.
- **Find in the list.** Ctrl+F (or the right-click menu) opens a small window that stays open while you work. Type a text: the files whose name, folder, modification date or creation date contains it are found (dates as `2024-05-01` or `14:30`). Next and Previous select the matches one by one, Select all selects them together, to remove or move them.
- **Command line.** The filters work in a script too, once all the paths are added: `--filter-name`, `--filter-regex`, `--filter-case`, `--filter-date`, `--filter-from`, `--filter-to`, `--filter-time-from`, `--filter-time-to`, `--filter-min-size`, `--filter-max-size`, and `--filter-remove` to take out what matches instead of keeping it. `--log-keep ok,error,unchanged` chooses what the log file keeps. A value that is not understood stops the run with exit code 4, before anything is renamed. Example: `antrenamer-qt.exe -b my.arb -af c:\data\* --filter-name "*.jpg;*.png" --filter-from 2024-05-01 -g -x`.
- **Flatpak.** A folder already given to the program through the system picker is no longer asked again: a file or a folder dropped from inside it is renamed without a question. This only concerns the Flatpak package, which is published with final versions (not with this beta).

Everything else is as in 3.3.1.

It is a pre-release: it is not offered as an update to someone who runs a final version, unless they tick "Also tell me about beta and release candidates" in the options.

### What to try

Add a folder with files of several kinds, put `*.jpg;*.png` in "Only files named": only the pictures should arrive. Then press F4, tick "Name matches", try a mask, then a regular expression such as `^IMG_\d+`, with and without "Case sensitive", and the "Remove the files that match" choice. Press Ctrl+F and type part of a name, then a date such as `2024-05`: step through the matches, then try "Select all". On the command line, try a filter with `-g -x` on a folder of copies. Tell me about anything that looks wrong or confusing.

### Tested

The unit tests pass on Windows (the engine, including the name filter and the command-line values, the actions editor and the filter window), and a real renaming through the command line with masks and a regular expression was checked. By hand, on Windows 11 and on Fedora (Flatpak), both built from the development branch: the mask when adding folders and in the drag and drop window, the name criterion of Filter files, Find in the list, and renaming with its undo with the enumeration, EXIF and date actions. For the Flatpak, the folders already given were checked on Fedora with the home folder, a pCloud drive, a USB key and a Synology NAS. Not tried yet: these packages installed, Windows 10, the Linux packages (`.deb` and AppImage), an upgrade over 3.3.1. Your feedback is welcome.

## Ant Renamer Qt 3.4.0-beta.1

Ant Renamer Qt est un portage C++/Qt 6 d'[Ant Renamer](https://www.antp.be/software/renamer/) d'Antoine Potten : renommage de fichiers par lots (remplacer, insérer, déplacer, supprimer, énumérer, changer la casse, expressions régulières, tags EXIF/IPTC/XMP/ID3...) sous Windows et Linux.

C'est la première bêta de la 3.4.0, « choisir les fichiers » : quels fichiers entrent dans la liste, et comment les y retrouver. Ce qui change :

- **Filtre par nom.** « Filtrer les fichiers » (F4) a un nouveau critère, « Le nom correspond » : une liste de masques (`*.jpg;IMG_??.png` : `*` et `?`, le nom entier doit correspondre, plusieurs masques séparés par `;`) ou une expression régulière (trouvée n'importe où dans le nom ; `^` et `$` l'accrochent au début et à la fin). Les majuscules ne comptent pas sauf si « Respecter la casse » est coché. Il se combine avec la date, l'heure de la journée et la taille, et une expression régulière qui ne se compile pas est refusée, avec la raison.
- **Seulement les fichiers nommés.** « Ajouter des dossiers » et la fenêtre du glisser-déposer ont une nouvelle ligne, avec les mêmes masques ou la même expression régulière : seuls les fichiers dont le nom correspond sont ajoutés. Les dossiers ne sont pas concernés. La ligne n'est pas retenue pour l'ajout suivant, pour qu'un masque oublié ne laisse jamais de fichiers de côté.
- **Rechercher dans la liste.** Ctrl+F (ou le menu du clic droit) ouvre une petite fenêtre qui reste ouverte pendant que vous travaillez. Tapez un texte : les fichiers dont le nom, le dossier, la date de modification ou la date de création le contient sont trouvés (dates sous la forme `2024-05-01` ou `14:30`). Suivant et Précédent sélectionnent les correspondances une à une, Tout sélectionner les sélectionne ensemble, pour les retirer ou les déplacer.
- **Ligne de commande.** Les filtres fonctionnent aussi dans un script, une fois tous les chemins ajoutés : `--filter-name`, `--filter-regex`, `--filter-case`, `--filter-date`, `--filter-from`, `--filter-to`, `--filter-time-from`, `--filter-time-to`, `--filter-min-size`, `--filter-max-size`, et `--filter-remove` pour retirer ce qui correspond au lieu de le garder. `--log-keep ok,error,unchanged` choisit ce que le fichier journal garde. Une valeur non comprise arrête l'exécution avec le code de sortie 4, avant de renommer quoi que ce soit. Exemple : `antrenamer-qt.exe -b mon.arb -af c:\data\* --filter-name "*.jpg;*.png" --filter-from 2024-05-01 -g -x`.
- **Flatpak.** Un dossier déjà donné au programme avec le sélecteur du système n'est plus redemandé : un fichier ou un dossier déposé depuis l'intérieur est renommé sans question. Cela ne concerne que le paquet Flatpak, qui est publié avec les versions finales (pas avec cette bêta).

Tout le reste est comme dans la 3.3.1.

C'est une préversion : elle n'est pas proposée comme mise à jour à quelqu'un qui utilise une version finale, sauf s'il coche « Me signaler aussi les versions bêta et release candidates » dans les options.

### Quoi essayer

Ajouter un dossier qui contient des fichiers de plusieurs sortes, mettre `*.jpg;*.png` dans « Seulement les fichiers nommés » : seules les images doivent arriver. Appuyer ensuite sur F4, cocher « Le nom correspond », essayer un masque, puis une expression régulière comme `^IMG_\d+`, avec et sans « Respecter la casse », et le choix « Retirer les fichiers qui correspondent ». Appuyer sur Ctrl+F et taper un bout de nom, puis une date comme `2024-05` : parcourir les correspondances, puis essayer « Tout sélectionner ». En ligne de commande, essayer un filtre avec `-g -x` sur un dossier de copies. Dites-moi tout ce qui paraît faux ou confus.

### Testé

Les tests unitaires réussissent sous Windows (le moteur, dont le filtre de nom et les valeurs de la ligne de commande, l'éditeur d'opérations et la fenêtre du filtre), et un vrai renommage par la ligne de commande avec des masques et une expression régulière a été vérifié. À la main, sous Windows 11 et sous Fedora (Flatpak), construits tous deux depuis la branche de développement : le masque à l'ajout de dossiers et dans la fenêtre du glisser-déposer, le critère de nom de Filtrer les fichiers, Rechercher dans la liste, et le renommage avec son annulation avec les opérations énumération, EXIF et date. Pour le Flatpak, les dossiers déjà donnés ont été vérifiés sous Fedora avec le dossier personnel, un disque pCloud, une clé USB et un NAS Synology. Pas encore essayé : ces paquets installés, Windows 10, les paquets Linux (`.deb` et AppImage), une mise à jour depuis la 3.3.1. Vos retours sont les bienvenus.
