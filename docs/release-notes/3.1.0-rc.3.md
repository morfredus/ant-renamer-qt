## Ant Renamer Qt 3.1.0-rc.3

Ant Renamer Qt is a C++/Qt 6 port of [Ant Renamer](https://www.antp.be/software/renamer/) by Antoine Potten: batch file renaming (replace, insert, move, delete, enumerate, change case, regular expressions, EXIF/IPTC/XMP/ID3 tags...) on Windows and Linux.

This is the third release candidate of 3.1, the version that follows the stable 3.0.0. Compared to 3.1.0-rc.2 there are five fixes, found by a review of the whole code:

- **A file that cannot be read when added** (gone, access denied, network share down) is no longer taken for a system file and skipped without a word (Windows).
- **CSV files** (exported preview, log): a file name starting with `=`, `+`, `-` or `@` is no longer run as a formula by Excel or LibreOffice.
- **A source file that is gone** counts as an error: the end-of-renaming summary shows it and `-q` returns the exit code 1.
- **A huge number in `%folderN%`** no longer freezes the program.
- **The notes of the Date and time action** no longer list the tags `c`, `ddddd` and `dddddd`, which do not exist (the help already said so).

Only fixes will be made, until the final 3.1.0. It is a pre-release: it is not offered as an update to someone who runs a final version, unless they tick "Also tell me about beta and release candidates" in the options.

### What 3.1 brings since 3.0.0

- **RAW files and more sidecar files follow their picture** when it is renamed (CR2, NEF, ORF, DNG... and `.xmp`, `.dop`, `.pp3`, `.cos`, `.acr`, `.on1`, `.thm`, `.aae`).
- **The log and the preview can be exported as CSV** (readable by Excel and LibreOffice, accents included), or as text.
- **The undo history is kept when the program is closed** (last 50 passes, by session, with a check of each file before undoing).
- **Silent command line** (`-q`) for scripts and context menus, with an exit code.
- **The modern layout is the default of a new installation**; existing settings keep their layout.
- **String replacement**: choice *Only at the beginning / Only at the end / Anywhere in the name*.
- **Language and interface applied at once**, no restart; the window keeps its size.
- **End of a renaming**: the number of files renamed and of errors.
- **Add folders**: a field and a *Paste from clipboard* button for the path.
- **New-version check** with beta and release candidates as an option, also offered by the Windows installer.
- **New icon**, Linux files signed with GPG, screenshots in the help, many corrections in the French text.

The details, version by version, are in the [WHATS_NEW](https://github.com/morfredus/ant-renamer-qt/blob/main/docs/WHATS_NEW.md).

## Ant Renamer Qt 3.1.0-rc.3

Ant Renamer Qt est un portage C++/Qt 6 d'[Ant Renamer](https://www.antp.be/software/renamer/) d'Antoine Potten : renommage de fichiers par lots (remplacer, insérer, déplacer, supprimer, énumérer, changer la casse, expressions régulières, tags EXIF/IPTC/XMP/ID3...) sous Windows et Linux.

C'est la troisième release candidate de la 3.1, la version qui suit la 3.0.0 stable. Par rapport à la 3.1.0-rc.2, cinq corrections, trouvées par une relecture de tout le code :

- **Un fichier illisible à l'ajout** (disparu, accès refusé, partage réseau coupé) n'est plus pris pour un fichier système et ignoré sans rien dire (Windows).
- **Fichiers CSV** (aperçu exporté, journal) : un nom de fichier qui commence par `=`, `+`, `-` ou `@` n'est plus exécuté comme une formule par Excel ou LibreOffice.
- **Un fichier source disparu** compte comme une erreur : le résumé de fin de renommage l'indique et `-q` rend le code de sortie 1.
- **Un très grand nombre dans `%folderN%`** ne bloque plus le programme.
- **Les notes de l'action Date et heure** ne listent plus les tags `c`, `ddddd` et `dddddd`, qui n'existent pas (l'aide le disait déjà).

Seuls des correctifs seront faits, jusqu'à la 3.1.0 finale. C'est une préversion : elle n'est pas proposée comme mise à jour à quelqu'un qui utilise une version finale, sauf s'il coche « Me signaler aussi les versions bêta et release candidates » dans les options.

### Ce que la 3.1 apporte depuis la 3.0.0

- **Les fichiers RAW et plus de fichiers associés suivent leur image** quand elle est renommée (CR2, NEF, ORF, DNG... et `.xmp`, `.dop`, `.pp3`, `.cos`, `.acr`, `.on1`, `.thm`, `.aae`).
- **Le journal et l'aperçu s'exportent en CSV** (lisible par Excel et LibreOffice, accents compris), ou en texte.
- **L'historique d'annulation est conservé à la fermeture du programme** (50 dernières passes, par session, avec une vérification de chaque fichier avant d'annuler).
- **Ligne de commande silencieuse** (`-q`) pour les scripts et les menus contextuels, avec un code de sortie.
- **La disposition moderne est celle d'une nouvelle installation** ; les réglages existants gardent leur disposition.
- **Remplacement de chaîne** : choix *Seulement au début / Seulement à la fin / N'importe où dans le nom*.
- **Langue et interface appliquées tout de suite**, sans redémarrage ; la fenêtre garde sa taille.
- **Fin d'un renommage** : le nombre de fichiers renommés et d'erreurs.
- **Ajouter des dossiers** : un champ et un bouton *Coller depuis le presse-papiers* pour le chemin.
- **Recherche de nouvelle version** avec les bêtas et release candidates en option, proposée aussi par l'installeur Windows.
- **Nouvelle icône**, fichiers Linux signés en GPG, captures d'écran dans l'aide, nombreuses corrections du texte français.

Le détail, version par version, est dans les [nouveautés](https://github.com/morfredus/ant-renamer-qt/blob/main/docs/WHATS_NEW_fr.md).

### Quoi essayer

Une release candidate est la version qui devient la finale si rien n'est trouvé. Les essais les plus utiles : une mise à jour par-dessus une version précédente (installeur, `.deb`), l'annulation après fermeture et réouverture du programme, vos renommages habituels, et la disposition moderne sur une nouvelle installation. Dites-moi ce qui ne marche pas, sur n'importe laquelle de vos machines.

### Testé

Les essais de paquets faits sur la 3.1.0-rc.1 valent toujours pour le code qui n'a pas changé. Pour la rc.3 : compilée sous Windows 11 (MinGW), tests du moteur réussis, avec de nouvelles vérifications (champs CSV, `%folderN%` géant, source manquante) ; les cinq corrections restent à essayer à la main sur les machines, et le test du panneau n'a pas pu être lancé sous Windows (il tourne sous Linux, dans la CI). Pas encore essayés : Debian 13 en x86-64 et les autres distributions. Vos retours sont les bienvenus.
