## Ant Renamer Qt 3.3.1

Ant Renamer Qt is a C++/Qt 6 port of [Ant Renamer](https://www.antp.be/software/renamer/) by Antoine Potten: batch file renaming (replace, insert, move, delete, enumerate, change case, regular expressions, EXIF/IPTC/XMP/ID3 tags...) on Windows and Linux.

This is a corrective version of the Flatpak package. Windows, the `.deb` and the AppImage are unchanged from 3.3.0.

- **Flatpak: no more access to your home folder.** 3.3.0 asked the Flatpak sandbox for `--filesystem=home`, so that files given one by one could be renamed. Flathub refused that permission. The package now sees only what you give it. A file given alone (drag and drop, file picker) or a folder dropped from the file manager is asked again: the program opens the system folder picker on the right folder, you confirm, and the system keeps the permission. The program then renames normally, sidecar files included. If you decline, nothing is changed and the file stays refused.
- **A drop the sandbox cannot see** (a file manager that sends paths it does not share) now gets a message instead of nothing.
- **French translation** of every message of the Flatpak handling (the warning of 3.3.0 was shown in English).
- Reminder from 3.3.0: with 3.2.0 from Flathub, files given one by one could vanish, left as hidden `.xdp-*` copies. If you were hit, show the hidden files (Alt+.) in the folder and copy each `.xdp-<new name>.<ext>.<random>` to `<new name>.<ext>`. The Flathub update to 3.3.1 comes some time after this release.

### Tested

The Flatpak was built from the sources of this version, without `--filesystem=home`, and tried on Fedora KDE (Dolphin): adding a folder (button), adding files, drag and drop of files and of a folder, renaming with sidecar files (`.xmp`, `.jpg.dop`, `.CR2`); no D-Bus message. Not tried: the permission kept after a restart of the program, files on another disk. The other packages are built from the same code as 3.3.0 and are not tried again.

## Ant Renamer Qt 3.3.1

Ant Renamer Qt est un portage C++/Qt 6 d'[Ant Renamer](https://www.antp.be/software/renamer/) d'Antoine Potten : renommage de fichiers par lots (remplacer, insérer, déplacer, supprimer, énumérer, changer la casse, expressions régulières, tags EXIF/IPTC/XMP/ID3...) sous Windows et Linux.

C'est une version corrective du paquet Flatpak. Windows, le `.deb` et l'AppImage sont inchangés par rapport à la 3.3.0.

- **Flatpak : plus d'accès à votre dossier personnel.** La 3.3.0 demandait au bac à sable Flatpak `--filesystem=home`, pour que les fichiers donnés un par un puissent être renommés. Flathub a refusé cette permission. Le paquet ne voit plus que ce qu'on lui donne. Un fichier donné seul (glisser-déposer, sélecteur de fichiers) ou un dossier déposé depuis le gestionnaire de fichiers est redemandé : le programme ouvre le sélecteur de dossier du système sur le bon dossier, vous confirmez, et le système garde l'autorisation. Le programme renomme ensuite normalement, fichiers associés compris. Si vous refusez, rien n'est modifié et le fichier reste refusé.
- **Un dépôt que le bac à sable ne voit pas** (un gestionnaire de fichiers qui envoie des chemins qu'il ne partage pas) affiche maintenant un message au lieu de ne rien faire.
- **Traduction française** de tous les messages de la gestion Flatpak (l'avertissement de la 3.3.0 s'affichait en anglais).
- Rappel de la 3.3.0 : avec la 3.2.0 de Flathub, des fichiers donnés un par un pouvaient disparaître, remplacés par des copies cachées `.xdp-*`. Si vous avez été touché, affichez les fichiers cachés (Alt+.) dans le dossier et copiez chaque `.xdp-<nouveau nom>.<ext>.<aléatoire>` en `<nouveau nom>.<ext>`. La mise à jour de Flathub vers la 3.3.1 arrive un certain temps après cette publication.

### Testé

Le Flatpak a été construit depuis les sources de cette version, sans `--filesystem=home`, et essayé sous Fedora KDE (Dolphin) : ajout d'un dossier (bouton), ajout de fichiers, glisser-déposer de fichiers et d'un dossier, renommage avec les fichiers associés (`.xmp`, `.jpg.dop`, `.CR2`) ; aucun message D-Bus. Non essayé : l'autorisation gardée après un redémarrage du programme, les fichiers d'un autre disque. Les autres paquets sont construits depuis le même code que la 3.3.0 et ne sont pas réessayés.
